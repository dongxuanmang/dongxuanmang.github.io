Agent 精读（十四）：给 Agent 接多模态，看原图、转文字、叫外援

这是《深入理解 AI Agent》精读专题的第十四篇。按顺序本该写第 4 章，但第 4 章还没读完，这一篇只写「感知工具 → 多模态感知」这一节；工具分类、MCP、工具发现、其它感知工具读完再补整章。读的是李博杰的开源书第 4 章。

给 Agent 接多模态，最容易想到的是“换个支持多模态的模型”。第 4 章这一节给的却是一道三选一的工程题：让主模型自己看、先把内容转成文字、还是把多模态模型包成工具叫外援。

三条路都能让 Agent“看见”图片、PDF、音频，但代价完全不同——这也是我口述时把后两条混成一条的原因。

三条路先摆出来

书里的原话是三条路径：模型原生的多模态处理、将多模态内容自动提取为文本再处理、把多模态模型封装为工具处理。翻译成人话：

第一条：让模型自己看

原生多模态处理是能力上限最高的一条。书里讲了原理：图像被 ViT 切成固定大小的 patch，每个 patch 序列化成向量，和文本词向量放进同一个高维语义空间；Transformer 的自注意力对文本 token 和图像 token 一视同仁，于是模型能直接“看到” PDF 的页面布局、图表和文字，理解图文之间的空间与语义关系。

代价是 token。一页 PDF 的截图往往要上千个 token，而那一页上的文字只有几百个；图片、视频更不用说。另外它有个前提：主模型得原生支持多模态——书里点名 GLM 5.2、DeepSeek V4 Flash 这类就不支持。

所以它不是“贵所以差”，而是“贵但上限高”：实验 4-3 里，图表分析和文档布局理解都是它表现最好。

第二条：先把字抠出来

提取为文本是一个两阶段过程：先用 OCR、音频转录这类工具把非文本内容转成纯文本，再交给语言模型。

它的账很划算：对文字为主的 PDF，一页文字几百 token，一页截图上千 token，差了一个量级。但代价是信息损失——版式、图表、图像在提取过程中全丢了。更要命的是它完全做不了需要视觉信息的查询：你问“这个图表哪个月最高”，它只看到一堆文字，答不了。

第三条：叫个外援

工具化多模态分析，是把多模态模型封装成工具：analyze_image、analyze_pdf、analyze_audio，入参是文件 + 自然语言问题，返回自然语言结论。主模型不直接看文件，只看到自己问的问题和工具给的答案。

这条路的两个好处：

  • 上下文里只有“问题 + 答案”，图片、视频的大量 token 不进来；
  • 工具内部的多模态模型不必是很强的 Agent，选型空间大——主模型不支持多模态时，这是比提取为文本更好的办法。

实验 4-3 的结论是：它在交互式场景最灵活，初步查询便宜，需要时可以调工具做高成本深度分析；但要一次性端到端深度理解，还是不如原生。

三条路怎么选

书里给了按内容类型选的原则：纯文字内容用文本提取，布局敏感的内容（UI 界面、复杂表格、设计稿）保留图像。

我读下来，两条容易混的路线其实差在一个词：全量翻译 vs 按需提问。提取为文本是把整份内容翻译成文字，成本固定、信息有损；工具化分析是带着问题去问，只拿回答，成本随问题走、能按需深挖。所以它们不是谁替代谁——

  • 主模型已经是多模态，且任务吃布局 → 原生
  • 纯文本扫描件，成本敏感 → 提取
  • 主模型不是多模态，或交互式、需要按需深挖 → 工具化

真实系统里还可以混着走：先提取做初筛，关键页面或图表再叫工具深挖。不过这是我的用法，书里只给了三条路和实验对照。

我一开始把后两条混成了一条

口述的时候，我把三条说成：直接使用多模态模型、使用多模态工具、多模态模型提供 API 让模型调用。现在回看，后两条被我揉成了一条，两个说法都不太准：

  • “使用多模态工具，最后产出对应的内容”——其实是提取为文本，两阶段 OCR/转录 → 纯文本 → 语言模型；它丢的是版式、图表、图像，不是笼统的“一些数据”。
  • “多模态模型直接提供 API 让模型调用”——其实是工具化分析：封装成工具，入参是文件 + 问题，返回文字结论；API 只是工具内部的实现，主模型看到的是工具，不是 API。

还有第 1 条，我当时只记住了“上下文占比大”，漏了它是能力上限最高的那一条。

Agent 精读（十三）：为什么最通用的 Agent，内核偏偏是写代码

这是《深入理解 AI Agent》精读专题的第十三篇，进入第 5 章「Coding Agent 与通用 Agent」的前半部分。读的是李博杰的开源书第 5 章从「Coding Agent」到「Coding Agent 的安全」——通用 Agent 的内核、七个工具、五种改文件方案，以及一套比提示词更硬的 Harness。后半部分「代码：通用 Agent 的元能力」六个方向还没读完，读完出下篇。

Manus 刚出来的时候，我以为它“通用”靠的是能上网、能点浏览器、能自己调研。读完第 5 章，书里给的答案更收敛：这些都是外壳，内核是一个 Coding Agent——一把 shell、七个基础工具、一个文件夹。

听着像暴论。但书里的推理很朴素：凡是高效的内容生成，最后几乎都落到代码上。

三类 Agent，三种动作空间

第 1 章说，Manus 出现之前，生产级 Agent 大多沿着三条相对独立的路线发展。换成“眼睛”和“手脚”的说法，一眼就能看出区别：

路线 眼睛（观察空间） 手脚（动作空间）
Deep Research 搜索结果、网页内容、论文摘要与引用 发查询、读网页、生成报告
Coding 需求、代码片段、目录列表、终端输出 搜代码、读写文件、执行命令
Computer Use 屏幕截图、DOM 或无障碍树 点击、输入、滚动、截图

三条路线的动作空间都是开放的——这是 Agent 和“只能从固定按钮里选”的传统程序的分水岭。Manus 的突破不是靠换一个更强的模型，而是把三者的观察空间和动作空间取了并集：虚拟浏览器扩大观察，文件系统、代码执行和命令行扩大动作。第 5 章接着追问：并集之后，为什么内核是 Coding，而不是另外两个？

理由一，几乎所有高效的产物最终都是代码。PPT、Word 本质上是 OOXML；PDF 报告可以由 Markdown、HTML 或 LaTeX 生成；数据分析和图表是 Python 脚本；连 GUI 里成功的一次操作序列，也可以被固化成可复用的代码。Deep Research 的搜索和信息综合，同样能落到 Web 请求与解析代码上。理由二，Computer Use 虽然最通用——什么界面都能点——但成本、延迟和稳定性都远不如直接调代码或 API。所以代码生成是效率最高、成本最低、可复用性最强的基座。

还有一层是文件系统。书里把它称作 Agent 的“中枢”：长期记忆存在 MEMORY.md 和按日期归档的 Markdown 日志里，产物写进文件，中间结果也落在文件里。选 Markdown 而不是向量数据库，乍看反直觉，其实很实用——用户可以直接打开文件阅读和修改记忆，Markdown 天然保留时间顺序，Git 还能版本控制和回滚。

这里要修正我口述时的一个判断。我口述时给三类分了个“危险程度”，说 Deep Research 危害性低。书里没有这么排。更准确的说法是看动作空间：Deep Research 以读为主，直接破坏性确实低；但它把不受信任的网页内容读进了上下文，恰恰是提示注入最顺手的入口。风险由“动作空间 + 信任边界”共同决定，不由品类决定。书里也专门划了边界：以开放任务为目标的通用 Agent 才以 Coding 为内核；垂直客服这类 Agent 仍以固定业务流程、领域工具和对话策略为核心，代码只是工具箱里的一件。

七个工具，五类动作

书里给了一个极简工具箱，七个工具：

  1. Code Interpreter：在隔离沙盒里执行 Python
  2. Bash：在终端里执行命令
  3. 读文件：读代码、配置、文档、日志
  4. 写文件：创建新文件，或完全重写
  5. 编辑文件：对现有文件做局部修改
  6. Glob：按模式找文件名，比如 **/*.py
  7. Grep：在文件内容里搜文本

七个工具覆盖五类动作：浏览目录、读、改、跑命令、找模式。

我口述的时候把它们归成了三类——执行（bash）、文件（读、写、改）、搜索（glob + grep）——正好漏掉了 Code Interpreter。顺便记一句容易混的：glob 找的是文件名，grep 找的是文件内容，这两个在脑子里总是挨着，作用完全不一样。

有意思的是，书里并不认为七个是必须的。OpenAI Codex 只用 shell + apply_patch 两个工具：shell 负责浏览、查找、读取，apply_patch 负责改文件。书里说“七个”只是为了讲清 Coding Agent 需要哪些基本能力。工具数量不是重点，动作类别覆盖全了才是。

再往下看一层，工具少不代表能力弱。一个最小任务：“把项目里的 TODO 整理成清单”——用 Grep 搜出三行 TODO，再用 Write 写一个 TODO_LIST.md，两个工具就够了。七个工具组合起来，已经能做很杂的任务。

改文件：难的不是改，是“说清楚改哪里”

七个工具里，最麻烦的是编辑文件。书里一句话点得很准：难点不在操作本身，而在于如何让 LLM 高效又可靠地告诉系统“改哪里、怎么改”。

自然语言说“把这段改一下”很容易，机器要执行，就得精确到某个位置、某段文本。为了在“人说话”和“机器执行”之间搭桥，业界试过五种方案。

一、差异描述 + Apply Model。模型不直接改文件，而是生成一份变更描述——类似 git diff 的差异文本，或者带“此处保持不变”省略标记的代码骨架。这份描述交给一个更小、更快的“应用模型”去合并。分工很漂亮：大模型管代码逻辑，小模型管文本操作。但合并环节很脆：变更描述和实际代码有微小出入时，要判断是不是同一处；文件里有多段相似代码时，可能合并到错的地方。Cursor 是这条路线的代表，后来基础模型变强，也不再用了。

二、旧字符串 → 新字符串。模型给出要被替换的原文和新文本，框架做字符串查找替换。优势是可预测、透明：原文存在且唯一就成功，否则失败，没有模棱两可。代价是删大段代码时必须完整输出所有原文，一个字符不对就匹配失败；同一段代码出现多次时，还得提供更长的上下文来消歧。Claude Code、Codex 和今天的 Cursor 都用这个方案。

三、行号定位。模型说“删除第 X 到 Y 行，插入新内容”。行号精确无歧义，删大段只给两个数字。但每次编辑后行号都会变化，一次思考输出多处编辑时，要约定都用初始行号来定位，否则越改越乱。

四、类 Vim 编辑命令。复制、剪切、粘贴，对“把函数从一处搬到另一处”很高效。但命令语法的学习负担大，强模型能玩转，小模型错误率明显上升。更深的洞察是使用者假设：Vim 是为人类设计的——人需要不断看到当前状态，再规划下一步的小操作；而模型的工作模式是长思考之后，批量做复杂的操作。

五、字符串首尾匹配。模型只给要删内容的开头几行和结尾几行，中间省略；框架用这对首尾去定位，唯一就准确。这是前几个方案的折中：删大段不必贴全文，又保留了内容匹配的可靠性。

这里还有三处是我口述时说岔了，顺手记下来：

  • 我最初只数出三种方案（diff、字符串替换、行号），漏了 Vim 命令和首尾匹配。首尾匹配恰恰是给“删大段要贴全文”开的药方，漏了它，这条演进线就断了。
  • 我说“删除文件会有大量文本输入”——准确说是删大段代码。删文件一个 rm 就完了。而且“大量文本”也不是字符串替换独有：diff 对删掉的行同样要逐行列出来，除非用省略标记的骨架。字符串替换真正独有的痛点是：必须逐字符复现原文，还要保证唯一。
  • 我说“行号在大文件里可能有问题”——书里讲的是行号会随每次编辑漂移，跟文件大小无关。大文件的问题反而在上下文预算，所以读文件工具要支持按行号范围读，并且每行带行号前缀；这样模型才能准确引用“第 42 行”。

五种方案看下来，没有纯赢家。它们在“定位的可靠性”和“表达的成本”之间来回换位置。更有意思的是，方案的流行跟着模型能力走：模型变强之后，专门做合并的 Apply Model 这层退休了；而“贴原文”这种最笨的办法，因为可预测、透明，反而回到主流。工具设计不是一锤子买卖，是跟模型能力此消彼长。

它成熟，不是因为模型强

这是本章最反直觉的一节。Coding Agent 是当前成熟度最高的 Agent 类型，但原因不是代码生成模型特别强——是测试套件、Linter、类型检查、Git 这些软件工程攒了几十年的基础设施，天然就是一套 Harness。代码编写是所有 Agent 任务里可验证性最高的一类。

书里用两个维度给任务分了个四象限：目标清不清晰、结果能不能自动验证。

  • 目标明确 + 自动验证：最佳区域，比如修复一个有测试用例的 bug
  • 目标明确 + 人工验证：吞吐量被人的审查速度卡住，比如重构
  • 目标模糊 + 自动验证：高效地往错误方向跑，比如用 linter 去优化“代码质量”
  • 两个都没有：难以启动，比如“让 UI 更好看”

Harness 的目标，就是把尽可能多的任务推向左上角。这也解释了为什么 Coding Agent 的成熟度最高——它的验收、反馈、回退都有现成的基础设施，不用从零搭。

落到工程上，是四件事：

  • 完成标准从“代码写完”改成“测试通过”。最常见的偷懒，就是写完不跑测试就报告任务完成。
  • 约束优先于指导。Linter 规则、类型约束、CI 检查是“做不了”，系统提示词里的“请遵循”只是“建议别做”。
  • 反馈越快、越结构化越好。文件一写完就跑 linter，把错误作为工具返回值带回去；错误信息越具体，模型自我纠正的成功率越高。
  • 回退要可靠。Git 分支、沙盒、快照，让 Agent 在安全网里大胆试错。

书里还给了一串具体机制：并行工具调用、流式执行与级联中止（一个调用失败只影响同一批里依赖它的调用，不连坐整个任务）、持久终端会话（cd 和虚拟环境不会每条命令丢一次）、以及把当前工作目录、git 分支、最近提交和变更概览作为状态栏，每轮追加进上下文。全是工程手段，没有一条靠提示词“求”模型做对。

故障恢复那节是同一个思路：故障按 API、工具、上下文、控制流分四层；可重试和不可重试要分开；恢复分静默重试、降级接续、暴露给用户三级；每条恢复路径都要有熔断上限——上下文压缩连续失败三次就放弃，这个阈值来自真实会话统计，不是拍脑袋。一句话，错误处理的边界不是单次请求，而是整个恢复循环。

先说结论：这场对谈值得认真读，但不值得照抄。

不值得照抄，是因为他讲的很多东西，是他这个位置才成立的。他有几千万美金级别的容错空间，说「零成本」和「先自由后财富」的成本极低。而我只有一次转型窗口。

所以我把整场内容过三道筛子：这条成立吗？对我成立吗？今天能做什么？

能抄的第一条：把身体当成一个有指标的项目

我原本的晨练是每天 30 分钟，属于「有动就行」。看完这场，我意识到问题不在时长，在结构——我练的是「运动」，不是「维持」。

他给的那套参数本身没有魔法，但每一条都可执行、可验证：蛋白质 140 到 150 克，硬拉深蹲这类复合动作，3 组 × 12 次，渐进超负荷，睡眠单独当指标看。

我查了一下薄肌原教程，他的数字基本对得上（后面细说）。原版给的是：蛋白质每公斤体重 1.6 到 2.0 克，口诀是「体重多少斤就吃多少克」——他 75 公斤正好 150 斤，对应 140 到 150 克。四大项是深蹲、硬拉、卧推、推举，每周三练。每组记重量次数，三组都达标且最后一组还剩两次力气才加重量。

这些不是发明，是力量训练的常识。他做对的事是把常识变成了可以每天打勾的仪表盘。

我真正要抄的是这个结构：

先定指标 → 每天记 → 每周看趋势 → 每月调一次

他有一句话我记下来了，因为它把「健康」从道德问题变成了会计问题：

“肌肉相当于是你最重要的一个银行账户，是你身上的现金。”

我不太吃「自律」这套叙事，但「账户余额」这套我吃。因为账户可以查，自律不能查。

具体到我这边的改造：不需要买 Oura Ring。手环记睡眠和步数，手机拍照记饮食，训练记录手写在备忘录，然后每天让 agent 汇总成一份 md 日报。这件事我本来就在做——只是对象是代码，不是身体。

这条我排第一，因为它回报最快。他说的「三个月立竿见影」不夸张，新手期的力量增长就是这么陡。而且它是我整个计划里唯一的「一票否决项」——其他任何事崩了都能重来，这个崩了不能。

能抄的第二条：把自己变成一个可被 AI 读取的人

这是全场技术上最对我胃口的一段。

他的做法是：所有东西存本地、存 Markdown、写 README，模型随时可换。今天用 Claude，明天清出去换 Codex，直接接手。

这句话在我们这行不算新词，叫「和模型解耦」，但把它用在个人生活上，我之前没认真做过。我一直在用 AI 干活，可我的生活数据是散的——健康在备忘录，读书笔记在博客草稿，项目记录在 git，财务在 Excel，互不相通。

他想做的是一件事：给「我这个人」建一个数据仓，AI 只是接在上面的处理器。

我打算照做的版本是这样：

门槛不是技术，是持续记录。他说先积累 2 到 4 个月再让 AI 分析，这个顺序很重要。大多数人对 AI 的用法是「今天问怎么赚钱」，相当于跟一个陌生人要人生建议。攒够数据之后，AI 才可能真的认识你。

顺带说个我很喜欢的细节：他吃饭前拍一张照片，吃完再拍一张。这比手记卡路里简单得多，还能自动算出吃了多少。这是典型的「降低记录摩擦」——记录方式只要够笨、够快，就能坚持。

不过要指出一处矛盾：他说这套零成本，但他自己配的是 Oura Ring 加 Claude Code 月费 200 刀。零成本的是方法，不是他的配置。 我的版本是手环加免费模型，效果打折，但能立刻开始。

能抄的第三条：先探图，再决定

「探图」这个比喻，我认为是整场最值钱的一个概念。

红警和星际里最笨的打法，是躲在基地里攒兵，从不侦察。等打起来才发现资源被挖光了，方向从一开始就错了。

他的解法是：买房前先看 100 套，选专业前先看 100 个。看完再决定。

这背后其实是最优停止问题。他给的粗略规则——前三个只用来建基准，之后一旦出现比基准好的立刻下手——大致对应 37% 法则的思路。对他来说精确解不重要，重要的是那个动作：把样本量提上来再决策。

这条对我直接有用，因为我现在最贵的一个决策就是转型方向。

按他说的做，我该干的是：让 AI 去扫 100 个 AI 相关岗位。不是看招聘要求，而是看每个岗位「进来之后每天在干什么」「三年后能去哪」「被 AI 替代的概率有多大」。扫完再定技术路线，而不是先写半年代码再发现方向错了。

这件事的成本大概一两天，而它能避免的是几个月的错投。

但这条我要加个边界：探图对可逆决策有效，对不可逆决策无效。

选技术栈、选方向、选城市，可以探图。身体不行——你不会有三套身体，让你先试完前三套再决定用哪套。感情也类似。所以他把人生说成「前 50% 先看，不急着下结论」，这个在职业上成立，在身体上不成立。这也是我把薄肌排在探图前面的原因：它是那个不给你试错期的项目。

能抄的第四条：写出来，才算存在

他有一句很暴的断言：

“如果一个东西未来没有成为 AI 的语料，这个东西就像从来没有发生过。”

这话夸张，但方向对。我拆三层看：

个人层面成立——经验只在脑子里，就无法被检索、复用、继承。写出来、结构化、放到网上，它才进入可检索的那一层。

行业层面成立——大量经验还停在口头交接和聊天记录里。谁能把它整理成机器能调用的形式，谁就在做基础设施。

文明层面过度——一个五千万人的古国没有文字记录，对人类确实等于不存在，但那是宏大叙事，不是个人行动指南。

对我最有价值的是它给「写博客」换了个理由。以前我把写博客当「输出倒逼输入」，属于学习方法。按他这个框架，写作是资产化——每篇写清楚的东西，都是可被别人和检索系统调用的接口，且不随平台消失。

我已经在做这件事。要升级的地方是：不只写「我读懂了什么」，还要写「我怎么判断的、踩了什么坑、放弃了什么」。前者是知识，人人可查；后者是经验，抄不走。

但这条要留一手，他讲得太满了。私有经验有价值，不是所有东西都该公开。我的界限是：方法论公开，执行细节保留。作品和思考发出去，具体的时机、报价、竞争判断留在本地。

能抄的第五条：黄毛和 Small Ego，拆成两个开关用

这两个词听起来打架：一个说「别人说什么你不管」，一个说「永远愿意听年轻人讲什么」。

他的处理是绑成一件事：没新证据时扛住噪音，有新证据时立刻改。

我觉得这个绑定还差一步——你需要一个规则，判断谁的话是噪音、谁的话是证据。 不然「扛住噪音」很容易变成「谁劝我都不听」，「Small Ego」很容易变成「谁的批评都往心里去」。

我给自己定了个很粗的规则：

说话的人 归类 处理方式
有相关一手经验，且说得出具体机制 证据 认真拆，能验证就去验证
只是转述社会期待（「这年纪还转行？」） 噪音 不解释，继续做
有利益相关（卖课、卖服务、竞争关系） 打折 听事实，不听结论
只说结论不说理由 待定 先放着，攒够样本再看

这条对我现在特别有用，因为转型期的噪音密度很高：来自前同事、家人、招聘方，也来自我自己。区分「谁的判断值得进脑子」，比「意志坚定」这种品质重要得多。

他还有一句我觉得比黄毛更值得抄：

“你越有钱越成功，其实理应来说你的 ego 应该更小才对。”

他管这叫一个 curse：越成功越容易觉得「我这么成功，所以我想的是对的」。这个提醒在今天尤其贵——模型几个月换一次代，任何一次成功都可能是上一个版本的运气。

能抄的第六条：多创造，少消费

这条最简单，也最容易被当鸡汤滑过去。

但他的论证不鸡汤。他用三个人讲了同一件事：

李煜当皇帝很失败，亡国、妻子被抢，悲痛之下写词，成了宋词的代表。当皇帝是消费，写词是创造。

诺贝尔发明炸药被骂「死亡商人」，一辈子没搞过学术，临死把遗产设成五个奖，一百多年后大家一听诺贝尔就觉得是学术权威。他做炸药时的意义，和他最终留下的东西，完全是两回事。

哈兰德的父亲也是个球员，踢得一般，但他爱踢球，还辅导儿子踢球。他自己没成巨星，可这个方向在儿子身上出了结果，连姓氏都留下了。

三个故事的共同点是：你在哪件事上创造，结果不一定落在你身上，但方向会传下去。

所以他的建议是「多创造，少消费，然后你做什么基本上都是对的」。我理解成一句话：把时间花在会留下东西的事情上，剩下的别太纠结。

对我来说，旅行、做饭、随笔这些原本归在「生活/滋养」的事情，按这个框架看其实是创造——只要它留下了记录和输出。这比我原来「先干活，剩下的时间才生活」的排法更好。

一个反转：他自己也没完全照着教程做

写到这儿，我去看了薄肌理论的原版，发现一件很有意思的事：孙宇晨抄对了参数，抄反了测量方式，还漏掉了一半。

先说他的学习能力，是真的强。

薄肌理论的原作者邵艾伦（Alan）自己讲过师承：大二读 Michael Matthews 的《Bigger Leaner Stronger》，建立了完整的健身基础。他称赞这本书的方式很特别——「它的好处是告诉你健身没什么秘诀」。他也承认「薄肌」不是一种肌肉，就是两件事：把肌肉练起来，别让脂肪盖住。这套东西在长文里逐条挂了 ACSM、ISSN、CDC、NIH 的出处。

也就是说，它本质上是主流减脂增肌共识的中文化加梗化。真正原创的不是方法，是命名和叙事。

而孙宇晨的执行参数对得相当准：蛋白质按体重斤数算、复合动作、渐进超负荷、蛋白粉加肌酸、控缺口。这说明他确实读了，而且读进去了。

但有三处偏差。

第一处，他把「慢变量」换成了「实时数据流」。

原教程的监测建议是：看每周平均体重，加固定位置的腰围（自然呼气、不收腹），两三周调一次，一次只改一项。原因写得很明白——体脂测量本身有误差，不要为了 12.0% 继续饿。

他用的却是：Oura Ring 抓睡眠和消耗、每日卡路里差、体脂率 29%。这是把一套「信慢变量」的朴素方法，改成了「信实时数据」。

我不觉得这是错，工程师都会这么改。但它有个副作用：实时数据噪音大，容易让人每天调整，反而看不出趋势。所以我的做法是两个都留——腰围和周均体重当主指标（稳），热量和训练量当过程指标（快反馈）。

第二处，他把 600 卡当成了脂肪燃烧的门槛。

原教程给的是：减脂期 -300 到 400 卡，减脂速度控制在每周 0.25% 到 0.5% 体重。他说的「摄入比消耗少 600 卡以内就是在烧脂肪」，把「缺口」说成了一个开关，但脂肪本来就是一直在烧的，缺口决定的是速度，不是「烧不烧」。

第三处，也是最明显的一处：他说「有氧都可以不做」。

原教程明确写了有氧：以步行为主，每周两次 20 到 30 分钟快走，逐步接近 150 分钟/周。这是 WHO 的建议线（150 到 300 分钟中等强度有氧，加每周两次力量），专业科普也直接反驳过「有氧会掉肌肉」这个说法。

而他自己在同一场对话里，用「心肺 25 分 + 肌肉 25 分」来论证健康重要。如果按他那句「有氧都可以不做」，心肺那 25 分只靠力量训练是拿不满的——最大摄氧量的提升主要靠有氧。

这就是一个内部矛盾：他先用 25 分开场，再亲手砍掉其中一半。

顺便说，「薄肌理论」本身也有它的争议。12% 这个数字，原作者在长文里留了余地（「审美参考，不是医学上的统一最佳值」），但视频版给了一套「画质分级」：10% 叫传奇皮肤，13% 是原皮肤，15% 以上 720P，18% 以上 420P。文字克制、视频煽动，这是它被群嘲的根源之一。营养师的意见很直接：男女体脂标准不同，不能拿一个数字要求所有人。也有健身博主实测：一个月 18 练、每月额外多消耗一万大卡，体脂还卡在 16%，想到 15% 以下「难于登天」。

光明日报的评论最锋利：这是「对一个极其普通的生活选择，起一个非常宏大的名字」。

所以这一节的结论是：这套理论可以抄，但要回到源头抄，别抄二手转述。 二手转述会丢掉限定语，也会添上新东西——比如「600 卡」和「不用有氧」，都不是原教程的话。

别抄的第一条：那个 100 分寿命模型

他反复用「心肺 25 分、肌肉 25 分、一共 100 分」这个框架。要说明的是，这是他和 AI 对话的产物，不是医学量表。

心肺适能和肌肉量确实都是全因死亡率的强预测因子，方向没问题。但把它折算成 25+25 分这种精度，医学上并不存在。他说这话的修辞价值远大于计量价值——他想讲的是「这是你唯一能主动拿满的部分」。

我抄那句话的意思，不抄那个数字。真要盯指标，就盯几个有实证的：血压、静息心率、腰围、体能（能不能连续做 20 个标准俯卧撑、能不能 12 分钟走完 1.5 公里）。

别抄的第二条：把某个具体体脂数字当目标

12% 对 20 岁、瘦、代谢好的男性可能不难；对中年人、对女性、对久坐的人来说，它可能是要付出激素和骨骼代价才够得着的数字。

我给自己定的目标不是体脂率，是行为指标：每周三次力量、两次有氧、蛋白质达标、睡够 7 小时。体脂率是结果，波动 ±2% 都属于测量噪音，不值得为它调整策略。

这一条其实也是我从他的失误里学到的：指标要选你控制得住的，别选你只能观测的。

别抄的第三条：crypto 全部化和「薄肌取代美金」

他的仓位故事很漂亮：2012 年就全部换掉，理由不是赚钱，是「系统升级」。

问题在于，这个故事只有他自己能讲。2012 年买入的持有成本，和今天进场是两个游戏。他说的「我不是为了赚钱，我是先更新系统」，事后来看当然对——但假如那件事没成，同一句话就会被读成赌徒的自我说服。

能借的是框架：判断一个东西是不是代表未来，看你愿不愿为「版本更新」付成本。不能借的是仓位：他的容错空间和我的不是一个量级。

「薄肌取代美金」这种话，当口号听就好。他自己也在同一场里说，钱只是个度量衡。

别抄的第四条：「百分百相信 AI」

这句是他这场里传播最广的，也最容易被误读。

看他的实际做法就知道：他会同时问 Claude、OpenAI、国内模型，三家取中；他会跟 AI 辩论，把自己过时的观点抛过去让 AI 反驳；他还说「90% 的时间让 AI 开飞机，10% 自己调」。

这是「极度信任 + 持续校验」，不是「AI 说什么就做什么」。

他自己演示了正确姿势：AI 说蛋白粉不是科技，他不是直接信，而是「它把原理一讲，我的理念就翻过来了」。他信的是原理，不是权威。

我要抄的是这个结构：让 AI 扩大信息面，让现实负责验收。任何无法被现实检验的 AI 建议，都只能当假设。

别抄的第五条：「30 岁前不买房不结婚」

他的原话比这温和：不是这些东西不好，是任何长期承诺都要用选择权买单。

这个道理我认。但他给的案例——「配偶不肯放弃月薪五千的工作，于是放弃月薪四万的机会」——是把人当成可自由重组的资产在算账。这个账算得对，但它不是唯一一种活法，也不该是所有人的人生公式。

我保留「机动性」这个原则，丢掉「该不该买房结婚」这个结论。机动性可以量化：现金留 6 个月、不背长期房贷、设备轻量、城市跟机会走。这些可执行。而「什么时候该结婚」不是从一个人的访谈里能推出来的。

顺带说，「先自由后财富」这段他讲得很轻巧——自由是主观的，你想自由就自由了。这话从一个已经财富自由的人嘴里说出来，成本接近于零。对现金流紧张的人，自由是有价格的。我可以接受「先争取选择权，再谈财富」这个顺序，但不接受「自由不需要门槛」这个说法。

一个我觉得他讲得最好的地方

整场里，他唯一一次说「我不知道」，是在婚姻和家庭那一段。

“我没结过婚，我也没有成立家庭，我还没有小孩，所以我也不敢贸然去说。”

一个 4 小时里几乎对每件事都给结论的人，在这一段停住了。他甚至说这是两亿人的时代问题，不是他一个人的问题。

我认为这个停顿比他说过的任何金句都更有价值。它是 Small Ego 的一次现场演示：在一个自己确实没有数据的地方，不硬编一个答案。

我的 30 天清单

筛完之后留下四件事，都很小，但都能立刻开始：

  1. 建 ~/life/ 数据仓：README 加四个子目录（health / learn / work / money），先不追求完整，每天往里扔一条。两个月后再让 AI 分析。
  2. 改造晨练结构：30 分钟从「有动就行」改成每周 3 次力量加 2 次有氧；蛋白质按体重算（1.6 到 2.0 克/公斤）；主指标用周均体重加腰围，每天只记一个过程数。
  3. 做一次探图：让 AI 扫 100 个 AI Agent 相关岗位，输出「岗位画像—能力映射—三年路径」，用它校准技术路线。
  4. 给博客加一档内容：除了精读，开始写「过程」——项目怎么决策、哪里踩坑、放弃了什么。这类内容才是抄不走的。

至于他那套孙学、黄毛、薄肌的命名体系，我一个都不打算用。名字是给传播用的，我只需要里面的动作。

真正让我记住这场对话的，是那句不像金句的话：

“你现在物质上是个富人，但身体上你是个穷人。”

去掉前半句，这句话对 20 到 40 岁的几乎所有人都成立。而它最难的地方在于——你得先承认自己穷，才愿意开始存。

孙宇晨 4 小时对谈精编：AI 时代什么都变便宜了，只有寿命在升值

这场对谈 4 小时 22 分。

对面坐着的是邵艾伦，千万粉的英语口语博主，也是「薄肌理论」的提出者。孙宇晨 36 岁，刚把体脂、肌肉、寿命这几件事当成一个新项目立项，并且用他习惯的方式推进——问 AI、建文档、上数据、出日报。

整场对话的起点是一个假设：如果今天你重新 20 岁，没有人脉、没有资源、一个月只有一千块可支配收入，你怎么重新开始？

他的答案不是推荐专业，也不是押注赛道，而是先装三套软件，再请一个掌舵者。

我完整读了一遍逐字稿，删掉寒暄、重复和转写噪音，把观点密度最高的部分重新排了一遍。为了可读性有压缩和合并，但没有替他改观点——包括那些我并不同意的观点。

说明：文中数字、比例、判断，多数是他和 AI 对话的产物，属于个人框架，不是医学结论，也不构成投资建议。个别明显属于转写错字的地方按上下文做了校正。

一、先装三套软件：孙学、薄肌、黄毛

他给 20 岁的自己开的方子，是三样东西。

孙学是大脑层面的。用他的话说，是「对金钱的理解、对财富自由的理解、对万事万物的理解，先用孙学升级一遍」。

薄肌是身体层面的。不追求夸张的体积，要的是有肌肉、低负担、体脂可控的长期状态。

黄毛是心态层面的，定义非常直白：

“黄毛理论就是说别人说什么你不管，自己认定对的就是充分执行。”

为什么第三样是必需品而不是选修？他的理由很实在：前两样一旦真的开始执行，一定会遭遇反弹。

“孙学和薄肌你但凡在今天的中国或者我们这个华人社会开始实施，绝对会遭到很多反弹……虽然是对的，但是会遭到很多打压以及嘲笑。”

后面他补了一句更狠的：你一旦又帅又有肌肉还有钱，在社会中一定会遭到嫉妒，这是百分之百的。

三样凑齐，在他看来就可以开工了。而且他强调成本：

“零成本，不需要任何钱。只是认知升级，一分钱不花。”

这句「一分钱不花」不是话术。他后面给的具体路径是：一个月可支配收入不到一千，就先装智谱或 Kimi 那类免费的 coding agent，把东西先跑起来；嫌 Claude Code 一个月 200 刀贵，就今天吃东家、明天吃西家。电脑没有，手机也行。

“电脑没有一台，手机都有。丢到手机里面也可以，都一样。”

二、把自己变成 AI 读得懂的人

大部分人对「用 AI」的理解，是打开对话框问问题。他讲的 AI 化，是另一件事：让你这个人变成一份可以被 AI 读取、调用、持续更新的档案。

他描述自己这两周的一天，几乎是流水线：

起床先工作，然后吃第一餐。吃饭前拍一张餐桌照片，吃完再拍一张，一起丢给 AI，让它算这一餐多少卡、按什么顺序吃（先吃高蛋白）。蛋白粉 25 克、肌酸 5 克。训练日练硬拉、深蹲这些大动作，训练日和非训练日一天交叉一次，教练在旁边拍视频，视频也发给 AI，逐组记录重量和次数，做渐进超负荷。手上戴 Oura Ring 抓睡眠和消耗，数据同样丢进去。摄入减去消耗，控制在 600 卡以内就是在烧脂肪；蛋白质定在 140 到 150 克，目标是同时增肌减脂。

然后是一份日报。

“可视化、数据化、可总结化，然后全部搞成 Markdown 文档。”

这句话里最值钱的不是「用了哪个模型」，而是后面两个动作：存在本地，和模型可换。

他的原话是，哪天要把 Claude Code 清出去换成 Codex，也可以直接接手，因为 README 都写好了。这背后是一个很工程师的判断：聊天框会消失，模型会过时，平台可能停服，但只要你把数据攥在自己手里，处理器是谁都无所谓。

所以他把那句老话又升了一版——以前是「不要跟微信聊天，要跟豆包聊」，现在是「用 API 跟全球的 AI 聊，所有文件保存在本地，再用 API 读取」。

但真正反直觉的是节奏。他并不急着让 AI 给答案：

“先积累个 2 到 4 个月，然后把所有的数据都收集齐，各种各样的数据数字化。”

为什么？因为 AI 对你的了解程度，等于你喂给它的信息量。你今天问怎么赚钱、明天问怎么学习、后天问为什么坚持不下去，每次提问都像第一次见面，它只能给你正确但无用的通用建议。

有真实数据，它才可能是外接大脑；没有数据，它只是个知识丰富陌生人。

至于「百分百相信 AI」这句容易被误读的话，他给出的实际操作是：一个问题同时问 Claude、OpenAI、国内模型，三家取中。后来还补了一句更准确的：90% 的时间让 AI 开飞机，10% 的时间自己调。

三、先探图，再决定

这是全场我最愿意称之为「真金」的一段。

年轻人最常见的焦虑是「我该选什么」。他的建议反过来：先别选。

“你要想买房了，做这个决定前先看 100 套房。你别买，你就看。”

看 100 套，是因为样本不足的时候，你根本不知道什么叫好。看完 100 套，价格、地段、户型、砍价空间，你自然有了基准线。100 个专业、100 个岗位、100 家公司，同理。

他甚至给了一个「最优停止」的粗略版本：前三套绝对不要买，那是用来建立基准的；第四套到第六套，一旦出现比前三套都好的，立刻下手。

然后他用游戏讲这件事，讲得比经济学教材清楚：

“我见过有的人，玩游戏永不探图，就是在家里闷头造兵……那个资源早都被别人挖光了。”

红警、星际里最笨的打法，是躲在基地里攒兵，从不侦察。聪明一点的做法，先造几个跑得快的单位，把整张地图探一遍，哪里有矿、对方出什么兵，全标出来，再决定造什么。

探图这件事在今天的关键变化是：它几乎免费了。

“有了足够的信息，你就不需要做决定了。”

这句值得抄下来。我们平常说的「决策困难」，多数时候不是选择能力差，是信息量不够。信息够了，答案自己会浮出来。

AI 最大的价值之一，就是把探图的成本压到了历史最低。而年轻人最容易犯的错，是反过来——用十年的努力，去弥补开始时十天的信息不足。

四、把计量单位从「楼底下」换成「全球」

他给年轻人找机会提了一个很具体的尺子：

“商机一定要全球性发现。千万不要局限于在家门口开个小卖部，挣楼底下老奶奶的钱。”

账是这么算的：中国 20 到 40 岁的年轻人有 4 亿，彼此服务当然卷；但把这 4 亿人武装起来，去服务全世界 80 亿人，再加上未来 20 亿 AI，那就是 100 亿的需求侧。

“80 亿人总有空隙，总有机会。你今天做这个行业不行，明天可以换别的行业。”

在这个尺度下，他列了几个他看好的方向，逻辑是同一条：哪里有大量数据已经产生、却没人处理。

数学——AI 把所有解题思路都抓进了模型，以前北大清华拿 IMO 多、菲尔兹奖少，卡在「导师知不知道这条路」；现在 AI 把那堵墙拆了，高中生拿着思路可以直接开干。

天文学——哈勃这类望远镜回传的数据极其枯燥，没人有时间处理，加个 AI 进去就是突破。

生物和基因——一个人的全基因组测序数据量大到没人分析，往下接健康管理和制药；再往外接保险这类跟寿命强相关的金融行业。

还有数据标注这种被瞧不起的活：他提醒，Scale AI 就是做数据标注起家的，卖给 Facebook 时一百多亿美金。

以及 crypto，理由不是价格，而是它天然适配 API 级的微额结算——传统金融最小单位是「分」，而机器和机器之间需要更细的计价颗粒度。

他给「价值」下的定义极简：

“如果你能让贵的地方用上便宜的，那不就体现出你的价值吗？”

他自己举的例子是 API 的区域定价：同一个模型，阿根廷、土耳其、尼日利亚的包月最便宜，美国最贵。这个差价本身就是机会，做 Token 中转就是把它抹平一点。这类例子不高级，但可执行——他要的不是「发现一个宏大需求」，而是「找一个还没被抹平的价差」。

他看机会的方式不是「哪个行业赚钱」，而是找断点：一边有供给、一边有需求，中间没连上；或者数据已经在那儿，但没人处理。创业不是先想一个宏大故事，是先找到一个断开的地方，把两端接起来。

五、AI 越强，身体反而越值钱

这是整场最反直觉的判断，也是他自己正在付钱下注的一条。

“AI 时代所有东西都会变得很便宜，唯一值钱的是寿命，所以年轻就是财富。”

逻辑很直接：当一个人可以同时指挥几十个 AI 干活，瓶颈就不再是缺助手，而是自己能不能长期在线。他把身体叫「碳基服务器」——硅基能力越强，越不能让碳基服务器提前宕机。

他还问过 AI 一个具体问题：人的寿命怎么算分？AI 给他的答案是心肺 25 分、肌肉 25 分、剩下的看基因和其他。他不止一次回到这个框架：

“前面那个 50 分心肺和肌肉，通过练薄肌你可以拿满。”

我在这里必须插一句：这个「100 分模型」是他和 AI 对话的产物，不是医学量表。心肺适能和肌肉量确实是全因死亡率的强预测因子，但把寿命折算成 25+25 分这种精度，医学上并不存在。他说这句话的修辞价值大于计量价值——他想讲的是：这是你唯一能主动拿满分的部分。

真正让我觉得这段有价值的，是他把肌肉重新定义成了一个金融概念：

“你物质上可能是个富人，但身体上你是个穷人。”

“肌肉相当于是你最重要的一个银行账户，是你身上的现金。”

这个比喻能成立的原因是：身体在缺能量、生大病的时候，是先扣肌肉的。所以肌肉不是装饰，是储备。趁现在有条件，把储备存进去。

他还举了一个反问，用来回应「马斯克、巴菲特、特朗普都不健身，凭什么说健身重要」：

“巴菲特是自己走进餐厅的，还是别人推轮椅推进去的？”

按他的版本，答案是被推进去的。这个反问把「别人怎么做」的参照系，换回了「你想怎么活到 80 岁」。他的判断是：这三个人在各自领域都极其聪明，唯独健康这一项，屁股决定脑袋——因为他们都是胖子，所以他们会为大肚子说话。

他自己那两周的转变也很典型。他承认以前有三个错误认知：练肌肉的人都是为了泡妞；有肌肉的人都上了科技；甚至自己发明过一套「肌肉和健康对立」的理论。

后来他一次问 AI，AI 说了一句让他震住的话：

“练薄肌就是领工资，就是把自己这个工资调高。”

再往后是行动：先去医院把血糖、血脂、好胆固醇坏胆固醇这些指标摸一遍底，再开始练。医生看了他一眼说——你是用了 AI 吧，你是第一个身体没症状、自己跑来要求查这些指标的病人。

他把这套叫主动健康管理：不是生病了才去医院，是不生病就在管。有钱人的错误想法是「我有钱，让医生帮我延长寿命」；而健康这件事，除了你自己，没人能替你管。等你在急救室门口喊「不惜一切代价」的时候，已经晚了。

为了说明「不能只顾一头」，他举了个例子：有些天才在专业领域强到无人能敌，却因为没早点看牙，牙齿出了不可逆的问题。他的原话是「磨刀不误砍柴工」——要做六边形战士，不能因为某一项很强，就放过其他项。

至于蛋白粉和肌酸，他也是被 AI 纠正过来的：

“我以为蛋白粉是不是有点科技……后来我才明白，蛋白粉其实就跟吃蛋白一样。”

25 克蛋白粉是为了解决「一天吃到 140 克蛋白质确实很难」这个现实问题，不是走捷径。

不过他也说了两句我认为需要打叉的话。一句是「有氧都可以不做，练力量本身就在提升心肺」；另一句是「600 卡以内就是在燃烧脂肪」。

编者注：这两条不是薄肌原教程的内容。原教程明确写了每周两次 20 到 30 分钟快走、逐步接近 150 分钟/周，也给了 -300~400 卡的缺口区间。我下一篇会专门讲这个差别——它比听起来重要，因为它关系到「心肺 25 分」到底怎么拿。

还有一个他给出的、关于时机的事实判断：肌肉量在 30 到 40 岁见顶，之后每年按 1% 到 2% 掉。所以这件事有窗口期：70 岁练只能保证你不坐轮椅，20 到 40 岁练，是给你 40 到 80 岁的生活质量做一次决定性投资。他算过账：每天 40 分钟。

六、黄毛与 Small Ego：一对看似矛盾的东西

黄毛讲的是抗噪。你走了一条不符合期待的路，一定有人说你。

他在这里给了一个很锋利的观察：妖魔化的通用手法，是把一件大事的目的「自私自利化」。

“妖魔化你的一个很重要的点，就是首先把你这个其实很重大的一个目的给他自私自利化。”

练肌肉是为了泡妞，做区块链是为了割韭菜，做 AI 是为了奴役人类——只要把你的动机说得很猥琐，事情本身对不对就不用讨论了。他举马斯克的纪录片、Sam Altman 亲属的采访，也举自己被编出来的「看牙不给钱」。

他的反驳是方法论层面的：评价一个人做了什么，而不是他为什么做。 哪怕那个健身博主真的出轨五十个人，也不能证明练肌肉是错的。

这跟他后面讲的「屁股决定脑袋」是同一件事：人们先用立场决定结论，再回头找理由。所以黄毛理论真正要扛的不是「有人反对你」，而是「反对你的人不谈事实只谈动机」。

他的态度是：

“别人说什么你不管，自己认定对的就是充分执行。”

但整场里还有另一半，他说得更重：Small Ego。

他拿张一鸣举例：不管多成功，永远愿意听年轻人讲什么，愿意学新东西。有新的就得学，有新的就得干。反过来，ego 大的公司，比如百度，就会被时代甩下去。

他还给了一个很反直觉的比例关系：

“你越有钱越成功，其实理应来说你的 ego 应该更小才对。因为这样才能保证你下一个版本成功。”

现实往往相反——越成功 ego 越大，因为你会有一种错觉：我这么成功，不就证明我想的是对的吗？他把这称为一个 curse。

所以黄毛和 Small Ego 并不矛盾，它们是一个执行姿态的两面：没有新证据的时候，扛住噪音往前推；一旦事实证明自己错了，立刻改。

而他自己的例子就摆在那儿。全网拿他的身高和体型嘲笑他，说他头大四肢小。他的处理方式是：先不因嘲笑动摇（黄毛），再看这些嘲笑里有没有一点道理（Small Ego），然后去问 AI 验证。

验证完，他不但开始练，还立刻把嘲讽他的那张图变成了自己的训练目标——先练腿，因为腿部肌肉最多。

七、认知决定论：不存在智商，只存在信息的多少

这场对话里他重复次数最多的一个词是「认知」。他甚至给了一句极端表述：

“世界上不存在智商这个东西，只存在信息的多少。”

他的论证方式很工程师：GPT-3 到 GPT-5，大家感觉是「智商的差距」，但后台看就是喂的信息量差了上千倍。所谓聪明，是信息加学习方式的外显。

这个说法当然过火了——信息量和处理能力不是一回事。但他真正想说的那件事是对的：认知会改变行为，行为会改变结果，然后差距会自我放大。

他用了两个模型讲这件事。

第一个是屁股决定脑袋。你现在的处境会替你说话。胖子会说健身有害，穷过的人会说钱没用，巴菲特会看不起比特币和马斯克——不是因为他笨，是因为他已经成功了，他的成功本身成了他的证据。

第二个是版本。

“版本不能回滚，只能往前更新。”

他把「一代版本一代神」讲成了一个通用规律：王者荣耀一个季度改一次英雄强度，地球 Online 两三年更新一次大版本。2018 年那个版本砍了房地产，加了 AI 加成——如果你还按旧版本练英雄，你会在几年后才发现自己练错了。

而这件事有个残酷的滞后性：

“虽迟但到。”

房产商的版本切换要三年才疼，马斯克不练肌肉要十五年到无可挽回。等痛感来的时候，通常已经来不及改。

八、翻译官：crypto、数学、和你的经验

这是全场逻辑最统一的一段。他把三件看起来无关的事，说成同一件事。

crypto：

“我们是将人类过去几千年的货币，翻译成 AI 和机器能听得懂的语言。”

数学也是：他设的孙宇晨奖，鼓励把数学证明翻译成 Lean 形式化证明——让机器能读懂推导。为什么重要？因为费马大定理、庞加莱猜想人类早就证出来了，但机器读不懂，就没法被吸收。他举了个很妙的例子：费马当年说「地方太小写不下」，那句没写下来的思路，让人类多花了一百多年。

再往外推一层，就是那条关于语料的断言：

“如果一个东西未来没有成为 AI 的语料，这个东西就像从来没有发生过。”

这句话粗听很暴，但拆开看是三件事：

一是个人层面——你的经验如果只存在脑子里、只散在聊天记录里，它就无法被检索、被复用、被继承。写出来、结构化、放到网上，它才进入生产系统。

二是行业层面——大量老师傅的手艺、团队的关键信息、失败案例的例外情况，都还停在口头交接里。谁把它们整理成机器能调用的形式，谁就在做 AI 时代的基础设施。

三是文明层面——他讲得最远：一个五千万人的古国如果没有文字记录，对 AI 来说就等于从未存在。

所以他把自媒体看得极重。不只是流量生意，而是「让所有人发言」这件事本身在数学上更接近真相——以前是主编定选题、记者执行，一个人的思维决定所有人怎么想；现在是所有人都在说，市场用脚投票。

他还讲了一个关于 AI 和人的边界的故事。纽约大学一位数学家把自己攻 NS 方程的思路讲给了 OpenAI，OpenAI 判断方向有希望，调了几千万美金的算力和几千个 agent 联合攻关，两天做出来了。学界骂 OpenAI 偷思路，他的角度反过来：从人类整体看，这个解被锁定了，进度条被拉快了。费马要是当年跟 AI 说两句，人类能省一百年。

“本人有可能是个悲剧，但是在全人类给你进度条给你拖快了。”

至于人和 AI 的分工，他的判断很清楚：AI 干的是「把所有已有思路抓出来、分析、往前探路」，它没法平地起高楼——你问它可控核聚变怎么做，它也不知道，因为人类还没做出来。人类提供的是那条从未存在过的思路。

九、先自由，后财富

他 2016 年那套「财富自由」讲了很多年，这场里升级了一句：

“财富自由其实还是先自由后财富。财富它是一个伴生品。”

我们把顺序搞反了：总以为先有钱才有资格自由。他的看法是反过来——自由是一种主观状态，你先决定自己自由，才有资格去做那些能带来财富的选择。

他打了个比方，说这两件事是螺旋：

你自由一点，就更容易获得财富一点；更容易财富一点，就更自由一点。

而具体到「怎么自由」，他给的是一句游牧民族的老话：

“逐水草而居。哪里有水，哪里有草，我们就去哪住。”

落到今天就是：哪里能发挥最大价值就去哪里，哪个行业在升值就换到哪个行业。钱在这里的作用不是目的，是数据——你能赚到钱，说明你在那个位置创造的价值大。

所以他不建议年轻人 30 岁前买房买车结婚。不是说这些东西不好，而是任何长期承诺都要用选择权去买单：

“明天早晨 OpenAI 说录取你来吧，来旧金山工作……你说我在北京买了个房，能不能让我在北京工作？那大概率 OpenAI 不同意，那你就失去这个机会了。”

他见过很优秀的人，因为配偶不愿放弃一份月薪五千的稳定工作，就放弃了月薪四万的异地机会。

年轻时最该攒的是能带走的东西：作品、能力、客户信任、项目经验、个人数据、可迁移的收入。而不是把自己钉在一个地方、一份按揭、一种必须维持的体面里。

他还顺手讲了个反面案例：中彩票的人为什么多数结局不好？因为那是一次性干预——没有配套的认知去承接，钱就成了放大器，放大你原本的错误。同理，突然给你一身肌肉，如果你没学过营养和主动健康管理，六个月后照样吃回原形。

而这一段最后还有一记回马枪。他说自己现在反而觉得，财富自由本身就是一个 myth：

“你以为你缺这个东西，你以为你想要那个东西。但是等你到达那个彼岸，你又发现我又缺回来。”

他举的例子特别具体：他没怎么上过班，所以特别想上班。想上到什么程度？愿意倒贴五千万美金，只为换一个 OpenAI 或 Anthropic 的 offer——因为他缺「从下往上看」的视角。反过来，上班的人最想的是不上班。

这就是他所谓的「缺啥补啥」。所以财富自由不是一个终点，更像一张能让你换个游戏通关的门票。

十、体验大于结论

聊到最后，话题从「怎么赢」转到了「为什么活」。

他把自己比作地球 Online 的玩家，现在还在探索期。

“体验大于结论。”

“人生本身的意义，可能就是你的体验的集合。”

这个转变不是凭空来的。他说小时候想过「为人类做贡献」「为地球做贡献」，后来上了一趟太空，这些答案全被打破了——人类过些年可能就不在地球了，那为地球做贡献这件事，参照系太小了。知道的越多，越不敢下结论。

所以他现在的策略是：前 50% 先看，先积累体验，不急着下判断。他甚至把这当成一种对抑郁情绪有用的说法——你不用立刻给人生找出意义，你只要先别急着结束，再看看，很多东西可以先试一试。

他用三个故事讲了同一件事：

李煜当皇帝当得很失败，亡国、妻子被抢，悲痛之下写词，结果成了宋词的代表人物。当皇帝是消费，写词是创造。

诺贝尔发明炸药被骂「死亡商人」，一辈子没搞过学术；临死把遗产设成五个奖，一百多年后大家一听诺贝尔就觉得学术权威。他做炸药时的意义，和他最终留下的东西，完全是两回事。

哈兰德的父亲也是个球员，踢得一般，但他爱踢球，还辅导儿子踢球。他自己没成为世界巨星，可这个「方向」在儿子身上出了结果，连姓氏都留下来了。

所以他的结论是：

“多创造，少消费，然后你做什么基本上都是对的。”

先上路，比想清楚为什么上路更重要。因为所有成为正确答案的人，在他成为正确答案之前，都不知道自己是对的——爱因斯坦是专利局职员，特朗普先做综艺和选美，诺贝尔没想过自己会变成学术符号。

他也给了三个 benchmark：马斯克代表工程与科技，巴菲特代表金融与长期主义，特朗普代表个人 IP 与跨界。他说自己不是只学一门武功——单练一门容易下判断说别人不行，而各家各派互相看不起的时候，恰恰是 ego 在替你关门。

至于婚姻和家庭，他给了一个罕见的诚实答案：

“我自己也在摸索……我没结过婚，我也没有成立家庭，我还没有小孩，所以我也不敢贸然去说。”

他说这是一个两亿人的时代问题，不是他一个人的问题。这场对话里唯一没有答案的一节，反而是最真实的一节。

最后：这套东西的最小可行版本

如果把 4 小时压成一条能今天就开始的线，大概是：

先用孙学换掉你对钱和机会的理解，用薄肌把身体这个一票否决项修好，用黄毛扛住执行路上的噪音，再用 Small Ego 保证你不被上一次成功锁死。

然后把 AI 接进来：不是为了问问题，是为了让你这个人变成一份可以被读取的数据；不是为了让它给你答案，是为了先把地图探开。

三件今天能做的事，他其实都说了：

一是把现有的东西全部 Markdown 化、放到本地一个文件夹里，装个免费 AI 就能开始。花的钱是零。

二是问 AI 要 100 个样本——100 套房、100 个专业、100 个岗位，看完再决定。

三是找一个 40 分钟的窗口去练力量，然后吃够蛋白质。

他有一句话，我认为是这 4 小时的标题：

“你现在物质上是个富人，但身体上你是个穷人。”

对 20 到 40 岁的人来说，这句话不用加「富人」也成立——我们几乎所有人，在身体这个账户上都是穷人。

随机切一刀，掷硬币定层：ANN 索引四个细节，与精确 KNN 的天花板

这篇不是读书笔记。《深入理解 AI Agent》第 3 章把 ANN 索引的结论给全了，我把其中四个细节单独拎出来实现了一遍：中垂面为什么等价于”离谁更近”、层号公式到底在抽什么、边数为什么不会膨胀、以及分层究竟贡献了多少。上一篇词有倒排，向量有图画的是轮廓，这一篇是轮廓下面的砖。最后还补了对照组：精确 KNN 为什么做不到一个都不漏。

我能背出结论，却答不上”节点里存了什么”

读 RAG 那几节，我很快就能说出”树适合静态库、图适合动态库、两者都要重排序”。这套话术成立，所以我也就没再往下问。

直到有人问我：那棵树里的内部节点，到底存了什么？层号是怎么定的？

我一个都答不上来。能复述结论和知道机器怎么转，中间隔着一次自己动手。于是我写了几个脚本，把 ANN 索引的几个关键处从头实现了一遍。

四个直觉，三个被推翻，最后一个把我自己的结论也推翻了。

一、我以为那棵树是”基于余弦”设计的

ANNOY 是”基于树”的。既然整个检索都在比余弦，树大概是按余弦切分空间、加速查找的吧？

不是。它用的是随机超平面——随机挑两个点，取它们连线的中垂面切一刀，一路递归到叶子。整个过程跟余弦毫无关系，甚至不看数据分布。

那为什么这样切能加速？因为有一条初等几何事实：

两个点的中垂面，就是到这两点距离相等的点的集合。

搞明白这一点之后，我觉得树的设计理解了。但我漏了一个更关键的问题：树切得准不准，其实根本不重要。

因为树只负责路由，不负责排序。它把查询送进一小片叶子就算完工，候选集最后还要用余弦精确算一遍。

这让我回头注意到一个之前完全没意识到的差异：

  • ANNOY 的近似是”候选集里可能根本不含真近邻”——因为它分割时压根不看余弦；
  • HNSW 的近似是”贪心游走可能从未走到真近邻”——但凡是走到的点，距离都是精确算的。

两者的距离计算都不近似。”近似”都发生在”有没有走到它”。

二、我以为稀疏和稠密是”静态”和”动态”

这个词我一开始是按”进化阶段”理解的：Word2Vec 是静态的，不够用，所以有了上下文感知；稀疏是老的，稠密是新的。

实际上这是两根正交的轴，被我压成了一根。

静态（每词一向量） 动态（看上下文）
稀疏 BM25 / TF-IDF / 词袋 SPLADE、BGE-M3 的 sparse 输出
稠密 Word2Vec BERT、BGE-M3 的 dense 输出

BM25 是稀疏的，但它属于静态那一侧，纯统计，没有任何神经网络。Word2Vec 是稠密的，但它也是静态的。

书里有个证据我一开始完全读漏了：BGE-M3 同时输出稠密、稀疏、多向量三种表示。一个模型同时给出两种”路线”，说明稀疏/稠密根本不是二选一的模型选项，而是两种表示形式。

那真正的界定标准是什么？零值比例只是表象。决定性的差异是每一维有没有明确含义：稀疏向量的每一维对应词表里的一个具体词，可枚举、可解释；稠密向量的每一维是人无法解释的，是模型学出来的。

HNSW 的核心卖点是”分层可导航小世界”。分层的道理听上去天经地义：上层节点稀疏，上层里的近邻在全局看来就相距很远，于是变成了长跳；查询从顶层入口一路贪心下降，先粗后细。

我第一版写的结论是”分层的 recall 明显更高”——数据出来是 0.478 对 0.480。那句话是我凭直觉写的，不是凭数据。

为什么分层在这里没用？

三个原因，缺一不可：

一、我漏了论文里真正的那个设计。 HNSW 的邻居选择不是”取最近的 M 个”，而有一个多样性启发式：候选若”离某个已选邻居”比”离新点”还近，就丢弃。它强制邻居方向分散，上层才有真正的长跳。我把这一步省了，上层就退化成”同一邻域的子采样”，分层的意义被抽空。

实测：加上这个启发式，扁平 NSW 的 recall 平均提升 0.020——比分层带来的差异还大。

二、规模不够。 分层的理论收益是搜索复杂度从准线性降到 O(log N)，这是 N 到百万级以上才拉开差距的渐进性质。我只有 6000 个点、层 0 每点还有 16 条边，扁平图本来就够好走了。

三、ef 太大。 层 0 的最佳优先搜索是一个宽度为 ef 的波束搜索，ef≥10 时它会自己”漫”到目标邻域，从哪儿出发关系不大。

这件事给我的教训比结论本身重要：分层是骨架，邻居选择启发式才是肌肉。 论文里那些看起来次要的实现细节，往往才是性能的真正来源。

边数会不会膨胀？不会。 每个点每层的度数有硬上限（层 0 是 2M，其余层是 M），一超就踢掉最远的。所以边数是 O(N·M)。实测固定 M=8：

HNSW 会漏，但漏的是”没走到”。 600 个点、ef_search=20、取 top-10，300 个查询里 top-1 命中率 95.3%。我挑了一个漏掉的案例解剖：真第 1 名相似度 0.8790，HNSW 找到的第 1 名只有 0.5859——去查这个真第 1 名有没有被访问过，答案是否，压根没走到。不是算错了，是没走到。

而 HNSW 本身不做重排序。它交出的候选已经按余弦排好了，但那只是向量相似度这个廉价信号。重排序用的是另一个贵得多的模型，把 query 和 chunk 拼在一起送进交叉编码器，能做词级交互。

有没有一个都不漏的办法？

前面五节讲的全是 ANN。但”近似”这个词，只有在有精确对照时才成立。所以最后把对照组补上。

先把两个词分清：

是什么 保证
KNN 问题：找离 q 最近的 k 个点 一个都不许漏
ANN 解法：快速找到”大概是最近的” 允许漏，用召回率衡量

所以 ANN 不是 KNN 的替代品，是它的妥协解法。

精确求解 KNN 有几条经典路线：暴力扫描、KD 树、Ball 树。我把它们都实现了一遍，第一件事是验证结果完全一致——这是 exact 的定义：

后两种树的加速全部来自同一个东西——三角不等式剪枝。树结构想跳过一整棵子树，必须先证明”那棵子树里不可能有比当前第 k 名更近的点”：

c 是子树包住的球的球心，r 是半径。q 到球心的距离减去半径，就是 q 到球面的最短可能距离——它若已经比当前第 k 名还远，整棵子树可以跳过。

KD 树是它的特例：切分面对应一个”无限薄的超平面”，用「q 到切分面的垂直距离」代替 d(q,c) - r。两者其实是同一个条件的两种写法。

那为什么不一直用精确方法？因为这条路有硬天花板。同样 N=3000，扫描不同维度：

柱子在 16 维掉到 0——索引白建了。橙色线一路爬到 0.89：当”最近的”和”最远的”几乎一样远，任何剪枝都无从下手。

Ball 树的负数是真实结果，不是 bug：我的向量都归一化在单位球面上（真实 RAG 正是这个形态），超球之间重叠严重，本来就难剪；而它每访问一个内部节点要额外算两次球心距离，剪不掉东西时这个固定开销就显露出来了。

这是维数灾难，不是工程没优化好。 KD 树、Ball 树、VP 树、cover tree，全都死在同一堵墙上。

那精确 KNN 还有用吗

有，而且不少场景必须用。

小库中库直接暴力算。 真实 RAG 里 faiss 的 IndexFlatIP 就是暴力扫描。几十万向量以内，很多系统根本不上 ANN——省掉一堆调参和召回率的不确定性。

需要 100% 召回。 法规、医疗、合规检索漏一条可能就是事故，95% 召回不可接受。

它是 ANN 的标尺。 调 ef_search 时拿什么判断召回够不够？拿精确 KNN 当真值。我前面测 HNSW 的 recall@10，基准就是暴力扫描。

重排序本身就是暴力 KNN。 粗召回 100 个候选后对这 100 个精确算距离，N 从百万变成了 100。

场景 推荐方案 理由
< 10 万向量 暴力 / IndexFlat 精确、零调参，速度够
10 万 ~ 100 万 ANN + 精确重排 粗排省时间，精排保质量
> 100 万 或高 QPS ANN（HNSW/IVF） 只能近似，靠调 ef 控召回
维度 < 20 KD 树 剪枝有效，精确且快
维度 128+ ANN 树结构已退化，别浪费
调 ANN 参数时 暴力当基准 没有真值就不知道召回多少

最后一行最容易被忽略：没有精确基准，你说不出自己的近似算法到底漏了多少。

一级：先问代码，别急着改

他给新用户的第一条建议有点反直觉：不要从写代码开始，先从对着自己的代码库提问开始。Anthropic 内部新人技术 onboarding 就是这么做的，结果是从两三周压到了两三天。

理由有三条。第一，问答阶段没有改文件的风险，却能同时练两件事：你怎么描述问题，以及它对这个项目究竟懂到哪一层。你会慢慢有边界感——什么任务一次能成，什么得来回两三轮。第二，零索引零配置：代码不上传、不建远程库、不用于训练，下载就能用。第三，这类任务容易验真，它答得对不对你自己一眼就知道。

他给的几个问题可以直接抄：”这个类实际是怎么被实例化的？”——它不是做一次文本搜索，而是去找真实的调用点；”这个函数为什么有 15 个参数？”——让它翻 git 历史，看这些参数是哪次提交加的、当时在解决什么、关联了哪个 issue；再比如用 WebFetch 去读 GitHub issue 拿上下文。他自己每周一在站会上都会问一句”我这周 ship 了什么”，让它从 git log 里捞一份清单出来，复制进文档就完事。

二级：动手之前，先要一份计划

一句自然语言就够了，不需要 plan mode 或任何特殊工具：

先头脑风暴几个方案，做个计划，拿给我看，写代码之前先征得我同意。

反例他讲得很实在：有人打开就一句”把这个 3000 行的功能实现了”——有时候一次就对，但有时候做出来的完全不是你想要的。先看一遍计划，通常一分钟就能发现它找错了入口、漏掉了兼容性，或者准备动三十个文件。

计划确认之后再给验收标准。他给的说法是保留现有 API、不引入新依赖、跑完相关测试和类型检查，最后汇报改了哪些文件、还有哪些风险没覆盖。另外他常念的一句咒语是 commit, push, pr：Claude 会自己去看 git log 摸清 commit 格式，建分支、提交、开 PR。这句话短得有点吓人，我在下一节末尾补一句提醒。

三级：给它一双眼睛（最值钱的一级）

这是全场反复强调的机制：当 Claude 有办法检验自己的成果，它就会自己迭代。

手段按领域分。后端和逻辑类用单元测试、集成测试、真实请求结果；Web 前端用 Puppeteer 截图——Anthropic 内部把这套做成了 MCP server 提交进仓库，全队共享，没有哪个工程师需要自己装；移动端用 iOS 模拟器截图；做界面就直接把设计稿图片拖进去，让它对着比。他的原话是：一次能做到不错的水平，迭代两三轮往往就接近完美。

但有个容易漏掉的细节，也是我从转写里特意标出来的一句：要给停止条件。 没有停止条件，它可能在一像素的视觉差异上无限消耗下去。比如”最多迭代三轮，最后汇报仍然不一致的地方”——重点不是这个数字，是让循环有出口。

这也就解释了开头那个痛点。prompt 的措辞只影响第一次输出长什么样，而回路决定了它能不能自己收敛到能用。前者是你在写，后者是它在跑。

四级：把踩过的坑写进 CLAUDE.md

CLAUDE.md 是一个每次会话开头都会被自动读入上下文的 Markdown 文件，Boris 管它叫”项目的记忆”。层级有五层：

层级 位置 用途
企业 企业根目录 全公司强制策略
用户 ~/.claude/CLAUDE.md 个人跨项目偏好
项目 项目根 CLAUDE.md 提交进 git，团队共享
个人 CLAUDE.local.md 不提交，只给自己
子目录 subdir/CLAUDE.md 在该目录干活时才载入

该写什么：常用的 bash 命令、代码风格约定、核心文件的位置、架构决策、MCP 工具的用法。然后他强调了一句：写短。 写长了会白白吃掉一大块上下文，而且通常也没那么有用。

两件容易被忽略的事。一是这套层级不只管记忆文件——斜杠命令、权限白名单与黑名单、MCP server 定义全都按同一套层级走。企业策略里可以把全公司都要跑的测试命令设成自动批准，也可以把某个 URL 永久拉黑、员工无法覆盖。二是记忆能就地写：输入 # 再跟一句话，就当场记进相应的文件，最典型的用法是”这个工具你用错了，以后这样用”；/memory 用来查看和编辑当前载入的所有记忆文件。他的建议是从共享的项目级上下文起步——一个人写一点，全队都受益。

五级：当 Unix 工具用，再谈并行

claude -p "..." 就是 SDK 形态的 CLI：可以传 prompt、限定允许使用的工具、指定 JSON 或流式 JSON 输出。他说 Claude Code 自己就是用这套 SDK 做的，Anthropic 拿它在 CI 和事故响应里跑。用法上要”当一个 Unix 工具想”：git status | claude -p "..." | jq，从对象存储里拉一份巨大的日志喂进去让它找异常，用 Sentry CLI 拉错误让它分析。他自己的判断是这条路才刚刚触到皮毛。

再往上一级才是并行：多开终端 tab、用 tmux 挂住 session、同一个仓库 check out 好几份、用 git worktree 做隔离。

这里有个我觉得比技巧更值得记的地方：他在台上说自己算个”普通用户”，一般一次只跑一个 Claude，最多开几个 tab 对应不同仓库；真正多开的是内外的重度用户。所以并行不是入门必修——前四级跑顺了再谈它，否则你只是把还没验证的改动同时铺开。

从一个闭环开始

如果这 28 分钟只带走一件东西，就带走那张图：先读懂代码 → 要一份计划 → 你确认 → 写代码 → 它自己验证 → 继续改。

一个能自己看见结果的闭环，比二十条 prompt 模板值钱。

具体怎么落地，他也给了最小版本，我建议按这个顺序跑一遍：挑手上一个真实的小需求，先让它把相关代码讲清楚（明确不许改文件）→ 要一份计划并挑一次刺 → 给它一个能验证的手段，哪怕只是”跑这条测试命令”→ 让它自己迭代到通过 → 最后把这次纠错写进 CLAUDE.md。五步一个闭环，跑顺了再谈放权、脚本化和并行。

Agent 精读（十二）：词有倒排，向量有图——RAG 检索的两条腿

这是《深入理解 AI Agent》精读专题的第十二篇，进入第 3 章后半部分：RAG 基础。读的是李博杰的开源书第三章「RAG 基础」与「混合检索」两节——分块、稠密/稀疏两条检索路线、融合与重排序。结构化索引（RAPTOR/GraphRAG）往后的部分还没读完，下篇继续。

从 100 万篇文档里找出那 2 篇

RAG 的流程一句话就能说完：用户提问 → 从知识库检索相关片段（top_k）→ 注入上下文 → LLM 基于上下文生成。「检索、增强、生成」三个词对应三段。它存在的理由也直白：模型训练数据有截止日期，外挂的知识库随时可更新。

真正的难点全在「检索」这一步：怎么做到又快又准。我学到这的时候犯了一个被当场抓住的错误——把 ANN（近似最近邻）加速说成了稀疏检索的优化。这次纠错逼我把两条完全不同的技术路线彻底分开，收获得到一句话：词有倒排，向量有图。下面按这句话展开。

先分块：检索的单元不是整篇文档

长文档不切开就没法检索：嵌入模型对输入长度有限制；一整篇文档压成一个向量，多个主题混在一起，哪个都不像（和上一篇 Enhanced Notes「段落越长、嵌入越稀」是同一个病）；检索本来就是要只取相关的那部分。

书里给了三类切法，我按”从笨到聪明”排列：

  1. 固定大小切分：按固定 token 数硬切，相邻块保留 10-20% 重叠——重叠是关键设计，防止关键句恰好被拦腰斩断。实现简单，但段落、代码、表格都可能被切坏
  2. 递归/结构感知切分：按章节、段落、句子的自然边界递归切，切大了就降级到更小的边界。生产系统的默认选择
  3. 语义切分：算相邻句子的嵌入相似度，在相似度”断崖”处下刀，让每块内部主题单一——利用向量在断开处做处理，切分质量最高，代价是每对相邻句都要算嵌入，贵

分块的固有缺陷先记一笔（书里埋的伏笔）：任何切分都会把片段和它的原始上下文切开——“该公司”指谁、出自哪份报告，留在了块外面。这个坑后文”上下文感知检索”会来填。

稠密路线：语义相近的向量也相近

嵌入（embedding）把词或句子变成一串数字，语义越近的文本向量越近。演进主线：Word2Vec 静态词向量 → 一词多义是它的死穴（bank 在 river bank 和 investment bank 里是同一个向量）→ BERT、BGE-M3 这类基于 Transformer 的上下文感知模型：同一个词在不同句子里有不同向量，从”词汇级”语义进化到”语境级”。

衡量”近”用余弦相似度，为什么用夹角不用距离？因为语义相似看方向是否一致，不看长短——两篇内容相同、长短不同的文档，向量方向一致、模长不同，余弦能正确判同。

那么，百万级文档怎么找 top_k？每条都要算一遍余弦就是 O(N)，快不起来——稠密向量没有共享的”词”，只有距离。所以只能造”近似”的索引结构（ANN）：

  • ANNOY（树）：随机超平面递归二分空间，查询沿树走 log(N) 步；建好就只读，加新向量要重建整片森林——静态库专用，省内存
  • HNSW（图）：每条向量是图上一个节点，跟近邻连边，然后分层：顶层节点稀少，越往下越密，最底层全量。查询从顶层入口贪心地走向离查询最近的邻居，走不动了就下沉一层。跳表思想就在分层里（ConcurrentSkipListMap 同款：上层稀疏、下层稠密、逐层缩小范围）；支持增量插入，动态库的选择，内存较高

「近似」的代价：贪心导航只保证局部最优，真近邻可能不在走过的路径上——拿一点召回精度换百倍速度。

稀疏路线：给词建二级索引

这一半我一开始完全是懵的，后来发现用自己天天在用的东西一讲就通了：倒排索引 = 按”词”建的二级索引。

写 SQL 按 content 查文档只能 LIKE 全表扫；倒排索引在写入时（离线）就建好「词 → 文档列表」的映射：

查询「模型蒸馏」= 两次索引点查 + 合并候选（并集）——10 篇里只有 4 篇被碰过，其余零成本跳过。Elasticsearch 的核心就是倒排索引，7.x 起默认相关性打分就是 BM25。以写入时建索引的一次性成本，换查询时的 O(1) 定位——这是每个后端都在做的交易，只是这次键从”主键”换成了”词”。

BM25 给候选打分，公式不用背，两个修正的直觉必须讲得出：

  • 稀有度压过次数（IDF）：「蒸馏」全库只有 2 篇有，「模型」有 3 篇——doc_1 里「蒸馏」出现 3 次、贡献反而大过出现 5 次的「模型」。词越稀有，单次命中的价值越高
  • 词频饱和：「退款」出现 10 次不比 5 次相关一倍——第 6 到 10 次只是重复啰嗦，次数的贡献收敛而不是线性增加（这是 BM25 对 TF-IDF 的第一个修正）
  • 长度归一化：同样出现 5 次，200 词的短文里它是主角，1000 词的长文里可能只是路过——避免有些词出现次数多、但文档也比较长、算出来占比却虚高（第二个修正）

还有一层本质差异值得单独说：倒排索引是精确的，一个不漏；ANN 是近似的，可能漏。稀疏精确、稠密近似——这两条路线连”错误方式”都不一样。

两条腿对照

混合检索：两条腿一起走

两条路线各有盲区：稀疏只做精确匹配、读不懂同义词（搜 “kitty” 找不到只写 “cat” 的文档），稠密懂语义但会漏关键词（搜 “HTTP-403” 可能返回”服务器错误”的泛泛讨论）。两个查询引擎都跑，然后对候选融合，再重新精确排名——这就是混合检索。

工程上三个阶段，各管一段：

  1. 并行召回：两路引擎各自返回一批候选
  2. RRF 融合：两路得分不可比（余弦是 0~1 的百分比，BM25 是 0 到几十的原始分）——扔掉得分、只看排名，每篇文档综合分 = Σ 1/(60 + rank)，谁在两路里都靠前谁赢
  3. 重排序：跨编码器把查询和文档拼成一段送入模型逐词比对，给融合后 top 50 精排——猎头筛简历是双编码器（文档向量预计算、快、无词级交互），面试官见本人是跨编码器（现跑、慢、准）。重排序不替代融合：融合决定谁进池，重排决定池内怎么排

还没读透的部分：三个指标

recall@k、MRR、nDCG 我还没细读，先把书的口径记在这里（读完回来补体感）：

  • recall@k：该找的找到了吗——正确文档进前 k 的查询比例，RAG 最吃这个指标
  • MRR：找得够靠前吗——第一个相关文档排名倒数的平均（第 1 名得 1 分，第 10 名只得 0.1）
  • nDCG：整条列表质量如何——排名越靠后的相关文档折扣越大

Agent 精读（十）：记住一个用户，四种存法，和一次跳出文本

这是《深入理解 AI Agent》精读专题的第十篇，进入第 3 章「用户记忆和知识库」。读的是李博杰的开源书第三章的前半部分——本章另一半 RAG 还没读完，读完后有下篇。

上下文管一次对话，这一章管一辈子

第 2 章读完的时候，我以为上下文工程就是 Agent 记忆的全部。第 3 章开头一句话把我点醒了：上一章解决的是单次交互的上下文管理，这一章要处理的是——对话结束之后，Agent 还记得什么。

书里把持久化记忆分成两个尺度：用户记忆面向单个用户，让 Agent 成为”懂你的助手”；知识库面向所有用户共享，让 Agent 成为”领域专家”。两者共用同一批底层技术（向量检索、知识压缩），也面对同样的三个麻烦：信息冲突、知识过期、检索不准。

我自己的一个归纳：如果上下文是 Agent 的”眼睛”（第 1 章的说法），那么用户记忆和知识库就是眼睛在时间维度上的延伸——上下文是此刻的观察，用户记忆是关于一个人的观察史，知识库是关于世界的观察沉淀。书里没有这么说，这是我读完这一章前半部分后自己接上的线，先记在这里。

先立尺子：我把两把尺子混成了一把

动手设计之前，书先回答”什么样的记忆系统算好”。这里我犯了一个被当场抓住的错误：我口述的时候把 LoCoMo 和三层次评估框架说成了一回事——“基础信息、隐藏信息、跨会话检索、整合能力”。其实它们是两把不同的尺子：

  • LoCoMo 是学术基准：平均约 300 轮、最多 35 个会话的超长对话，任务是问答（单跳、多跳、时间推理、开放域、对抗性五类）加事件摘要和多模态生成。它是被动问答——用户问了才答。
  • 三层次框架是书作者为 Agent 场景自建的：第一层基础回忆（准确存取用户直接给出的信息），第二层多会话检索（跨会话、跨对象把相关信息全部捞出来再推理——用户有两辆车，你得问”保养哪辆”，而不是猜一辆），第三层主动服务（没人问，系统自己发现护照快过期了并预警）。

分清它们的关键在第三层：主动服务是无指令的，LoCoMo 的任何一类问题都装不下它——问答题永远有一个提问者，而主动服务的起点恰恰是没人提问。作者自建尺子，就是为了量出 LoCoMo 够不着的那一段。

记忆三问：三套正交的分类体系

书里给了三套分类体系，我一开始只说出了两套。它们各自回答一个问题，而且互相正交、可以自由组合：

分类体系 回答的问题 具体类别
记忆层次 存在哪里？ 轨迹（当前会话）、用户长期记忆（跨会话）、业务状态（任务阶段）
存储格式 怎么存？ Simple Notes、Enhanced Notes、JSON Cards、Advanced JSON Cards
认知类型 存什么？ 情景记忆（具体事件）、语义记忆（一般知识）、程序记忆（行为流程）

轨迹和长期记忆的分野，原文有一句我很喜欢的对照：轨迹是流水账，长期记忆是档案。轨迹 append-only、不可变；长期记忆被反复改写、合并、淘汰。存什么的三个类型也好分：”订了下周五去东京的航班”是情景，”用户是素食者”是语义，”先搜直飞→确认座位→用常旅客号”是程序。

正交的意思是：一条”用户偏好靠窗座位”的语义记忆，可以用 Simple Notes 存在长期记忆里；一段订票流程的程序记忆，也可以用 Advanced JSON Cards 存。选格式看工程，选类型看业务。

四种存法，是一条修 bug 链

同一条信息（”我在 TechCorp 任高级工程师，负责推荐系统，带 5 人团队”），有四种存法。我第一次学的时候把它们当成四个并列的选项去背，越背越乱；后来把它们看成一条链才真正记住——每往右一步，都是在修上一步的 bug，同时引入新的 bug。

  1. Simple Notes 拆成原子事实，一条一行：更新是 O(1) 的，改”职位”那行就行，便宜。但关联性丢了——三条碎片之间没有任何联系，问”他的职业背景”要靠模型现场拼图，而且拼的时候可能把不同人的碎片拼到一起。
  2. Enhanced Notes 存整段叙事：语义完整，读到一段就拿到全部上下文。但同一个事实会在多个段落里重复出现，改一处要记得改所有处，漏一处，记忆库就自相矛盾。
  3. JSON Cards 三层结构化（类别→子类别→键值）：改 work.position.title 一个字段，别的不动，更新终于安全了。但它是刚性分类——我卡住的地方就在这。我以为”周末用 Python 开发个人项目”存不好是因为”信息不结构化”，错了：这条信息的三个维度（时间偏好、技术偏好、活动类型）个个明确，问题是它横跨三个类别，刚性单分类塞不下。问题不在信息，在容器。
  4. Advanced JSON Cards 在结构之上加元数据：backstory（为什么存这条）、person（这条信息关于谁）、relationship（这个人和用户什么关系）、时间戳。它解决的是理解层面的歧义——“张医生”是用户自己的牙医，还是用户父亲的心脏科医生？简单键值存储在”帮我安排家人的年度体检”这种请求面前根本无法区分为谁。代价：每次写入要模型做更多提取判断，生成维护成本高。

我在验收练习里自己拆过一条信息，用它说明第 1 步的坑最直观：”用户提到他母亲有高血压，最近开始服用氨氯地平”——用 Simple Notes 拆成两条原子事实，隐患立刻出现：这两行和记忆库里的其他行没有关联，三个月后用户说”我爸头晕想买降压药”，检索命中”服用氨氯地平”时，这条记忆没有”关于谁”的字段，母亲、父亲、用户自己的信息会混。这就是为什么健康这种关键信息值得用 Advanced 存：person 填”母亲”，relationship 填 family/mother，backstory 填”哪次对话、什么场景提到的”——注意 backstory 填的是出处，不是事实的复述。

四种存法的落点不是选一个最强的，而是混合：关键且少量的信息（偏好、家人关系、健康）用 Advanced 保证可检索可推理；大量且非关键的对话事实用 Simple 控制成本。

第五种存法：把记忆写成代码

四种格式本质上都是文本。文本擅长召回单条事实，但有三类活它干不了，只能交给 LLM”心算”：聚合（用户今年出国几次）、冲突检测（在用药和过敏史逐条交叉比对）、约束执行（护照有效期距出发日期不足 180 天就预警）。

心算的问题不是”模型完全不会算”，而是不确定：同一道题两次答案可能不同，长列表会数漏，算错了不留痕迹。数漏一次出国次数无所谓，过敏药漏检一条是医疗事故。这三类活要求每次结果一致、可审计、零遗漏——概率模型给不了这个保证。

书里给的第五种形态是 User as Code（作者自己的论文）：把用户状态改成带类型的可执行对象，把规则写成普通函数。数”2025 年出国几次”是一条查询语句；过敏药冲突是一个双重循环；护照检查是状态更新后自动跑的一个函数——不等用户来问。

状态怎么维护？书里用了数据库的味道很浓的方案：预写日志 + 检查点。会话结束后先把事实追加到只增日志，再定期从完整日志重建带类型的状态。我一开始以为这是为了省开销、批量处理，其实方向反了——日志是真相源，状态是派生缓存：

  • 重建代码有 bug、状态算错了？修好代码，从检查点重放日志，正确状态重新出来，证据一步没丢。
  • 反例是 Mem0 v2：写入时直接 UPDATE/DELETE，一次错误的更新不可逆地丢掉原始数据，错了就永远错了。v3 改成仅追加写入、把冲突判断挪到检索时，LoCoMo 从 71.4 涨到 92.5——教科书级的教训。

什么样的信息适合写成代码？我拷打自己得出的判据：带类型的数据 + 可判定的规则。护照有效期（date 类型 + 180 天规则）适合；常旅客号适合结构化存储；”用户是素食者”可以结构化成布尔字段，但用途只是订餐时召回提醒，不需要计算；”用户最近情绪低落””喜欢性价比高的产品”是模糊的主观状态，写不出判定函数，留在文本里。

而这一节真正让我觉得值钱的是一个时机问题：文本格式的记忆，计算发生在使用时，而且没有触发点——用户直接说”帮我订下周五去东京”，模型大概率根本不会想起来去算护照有效期。代码化的记忆，计算发生在写入时/事件时，由系统保证执行。算得准只是副产品，一定算才是本质——第三层”主动服务”的工程地基就在这里。

收进一张卡片

这一章前半部分读完，能收进一张卡片：

  • 记忆三问：存在哪里（轨迹/长期记忆/业务状态）、怎么存（四种格式）、存什么（情景/语义/程序），三套体系正交
  • 四种存法是一条修 bug 链：Simple 改得快拼不回，Enhanced 拼得全改不动，JSON Cards 解决”改”，Advanced 解决”理解”，生产上按”关键且少量→Advanced，大量且非关键→Simple”混合
  • 聚合、冲突检测、约束执行不能靠 LLM 心算；User as Code 用带类型状态 + 规则函数 + 预写日志（日志是真相源，状态可重建）
  • 代码化的判据：带类型的数据 + 可判定的规则；回报：计算时机从使用时移到写入时，主动服务从”祈祷模型想起来”变成”系统保证会跑”
