转型做 Agent 开发之后，我有个不好意思说出口的执念：总觉得 agent 干不好活，是因为模型不够聪明。于是换更好的模型、堆更长的上下文、找更玄的提示词——直到读完李博杰[《深入理解 AI Agent》](https://github.com/bojieli/ai-agent-book)的第一章，才发现这本书开篇就在拆我的台。

## 公式

书里给了一个看起来平平无奇的公式：

```
Agent = LLM + 上下文 + 工具
```

大脑、眼睛、手脚，没什么玄的。真正让我停下划线笔的是它的生产形态：

```
Agent = Model + Harness
Harness = 上下文管理 + 工具接口 + 约束 + 验证 + 纠正
```

我原以为 Harness 是个工程脚手架，读完才发现它是个治理层。模型负责「想」，Harness 负责让「想」变成「可靠地做」——权限收口在它手上，验证在它手上，出错回滚也在它手上。

而且书里把边界划得很死：Harness 在 Agent 边界内、**模型之外**。沙箱里随行动变化的文件、外部的数据库、网页、用户，统统算环境——哪怕它们和 Agent 跑在同一个进程里。这个边界以后判断「一段代码该不该归入 Harness」全靠它。

## 判词

Agent 和外部世界打交道，只走两扇门：观察通道和动作接口。

上下文是眼睛。它不是我以前理解的「聊天记录」，而是每个决策点模型能看到的全部——环境观察、用户记忆、领域知识、自身状态、任务进展。没进上下文的信息，对模型来说不存在。

工具是手脚。没被动作接口放行的操作，模型就算知道该怎么办，也只能停留在文字建议上。

所以原文那句话，我愿意称之为全书第一章的判词：

> 许多看似需要更聪明模型的问题，其实只是接口问题。

这话有实证。LangChain 在 Terminal Bench 2.0 上把得分从 52.8% 提到 66.5%，排行榜三十名开外冲进前五——改的不是模型，是 Harness：让 Agent 自动检查自己的执行结果、检测是否在绕圈、优化思考策略。

各家模型越来越接近的今天，分出高下的地方，在模型之外。

## 扩张

第一章后半段的发展史，我读出了一个 pattern：**观察空间和动作空间的扩张**。

最早，Deep Research、Coding、Computer Use 三条路线各自为政，各家 agent 活在各自的玻璃房里。Manus 是第一个把三者并进一个产品的——云端虚拟机里，虚拟浏览器把观察空间拉开，文件系统和命令行把动作空间拉开。

到 OpenClaw 又往外推了一层：干脆跑在你自己的电脑上，本地优先。WhatsApp、Telegram 随叫随到；授权之后，Drive、Notion、本地文件——你散落在各处的数字生活——都进了同一个观察空间。

回头看这条线：谁扩大了观察与动作空间，谁就重新定义了 agent 的能力边界。

## 下一步

第二章是全书最关键的一章（官方原话），讲上下文工程。在那之前，先把第一章的 `context` 实验跑起来——纸上得来终觉浅，最小 Harness 值得亲手搭一遍。
